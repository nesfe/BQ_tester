# Регистры, определение версии и управление батареей

Функциональность входит в тестовую версию **2.2.0** вместе с обновлёнными графиками. Релиз 2.1.0 не изменяется. Основной экран сохраняет оформление; новая сворачиваемая панель **Registers & commands** находится перед Debug Console.

## Определение прошивки

После подключения приложение читает `DeviceType (0x0001)`, `FirmwareVersion (0x0002)` и `HardwareVersion (0x0003)`. Проверяются размер ответов и идентификатор BQ40Z50 `0x4500`; версия и номер сборки берутся из ответа самой батареи. Профиль выбирается по основной версии прошивки (исходная версия и R1–R5), а порядок байтов FirmwareVersion определяется по полю Device Number. Исходный ответ также сохраняется в сведениях об устройстве.

Если идентификация не удалась или прошивка неизвестна, обычная телеметрия остаётся доступной, а каталог исполнения не выбирается наугад. Повторить чтение можно кнопкой **Detect firmware**. Профили описывают стандартные прошивки TI; OEM-изменения и будущие сборки требуют проверки по их документации.

## Каталог

Источник каталога — заголовки разделов команд, таблицы битов и таблицы Data Flash в TRM каждой ревизии. Метаданные содержат адрес, протокол, доступ, тип, длину, единицы, номер раздела и ссылку на страницу TI. Команды совместимости Reset/ROM и объединённый в документации заголовок F080/F081 перечислены отдельно.

Категории:

- **SBS registers** — стандартные и расширенные команды SBS, включая чтение/запись поддерживаемых параметров.
- **ManufacturerAccess** — идентификация, статусы, диагностические блоки, lifetime/gauging, управление FET, Gauging, PF, Fuse, LED, Sleep/Shutdown, Reset, калибровка и ROM.
- **Control commands** — все команды записи/управления, включая ключевые последовательности.
- **Data Flash** — именованные физические адреса и доступ по адресу в диапазоне `0x4000–0x5FFF` для полей, не выделенных в таблице в отдельную строку.

Поиск работает по адресу, названию, группе и именам битов. На странице не более 40 строк. **Read selected** читает выбранную запись. **Read visible** последовательно читает видимые диагностические записи; Data Flash, ключи и зависимый от предыдущего запроса ManufacturerData в массовый опрос не входят. **Stop after current read** отменяет оставшуюся очередь.

Целые значения и текст декодируются по метаданным; полный ответ всегда доступен в HEX. Статусные биты подписаны согласно выбранной ревизии. Для H-полей без именованной карты показываются исходные биты без выдуманных названий. Смешанные блоки и специальные числовые форматы остаются в HEX: это не полноценный редактор всех структур bqStudio. Ссылка **TI documentation** ведёт к описанию конкретной записи.

Чтения выполняются по запросу, а не добавляются целиком в быстрый цикл графиков. Все операции с EV2400 сериализованы. Ответы старого подключения не применяются к новой батарее. Расшифровка SafetyStatus/OperationStatus для событий графика также использует определённую ревизию.

## Исполнение и запись

1. Выберите запись и проверьте описание и документацию.
2. Для word-записи задайте исходное значение 0–65535 (отрицательный I2 передаётся в дополнительном коде). Для блока введите байты HEX **без** кода команды/адреса. Ключевая последовательность — два слова little-endian, всего четыре байта. Длины SecurityKeys различаются между ревизиями и проверяются отдельно.
3. Введите идентификатор выбранной команды и нажмите **Execute once…**. Отдельное окно Electron показывает действие и параметры; по умолчанию выбрана отмена.
4. Проверьте результат и фактический статус батареи. Подтверждение транспорта означает получение команды интерфейсом, но не доказывает выполнение всех условий внутри контроллера.

Перед записью проверяются профиль, доступ команды, размеры параметров, диапазон адресов и актуальное состояние SEALED/UNSEALED/FULL ACCESS. Ключи не подставляются автоматически, не записываются в журнал и исключены из экспорта снимка. Обычный ввод ключей и программирование AuthenticationKey поддерживаются; однократное программирование ключа в secure memory — отдельная процедура TI, не выполняемая этой командой.

Особые случаи:

- `RSOCWrite` принимает двухбайтовое значение 0–100, например `64 00` = 100%; оно может быть перезаписано следующим расчётом gauging.
- `Shutdown` в SEALED отправляет документированную последовательность из двух команд. После Shutdown/Reset/IATA Shutdown соединение закрывается; подключитесь снова, когда батарея готова.
- В ROM и при выводе калибровочных данных нормальный опрос и графики приостанавливаются. Доступны соответствующие команды выхода. ROM exit использует SMBus Send Byte `0x08`; загрузчик файлов прошивки в эту панель не входит.
- При ошибке записи автоматического повтора нет; опрос приостанавливается до явного восстановления. Это исключает повторное переключение FET или повторную запись после неопределённого ответа.
- Запись Data Flash ограничена 1–32 байтами за действие. Ответ чтения проверяется по длине и эху адреса; после записи выполняется чтение обратно и сравнение. При несовпадении показывается ошибка без повторной записи.

**Export snapshot** сохраняет идентификацию и прочитанные диагностические результаты в JSON. Ключи, аутентификационные данные и Data Flash в этот файл не включаются. CSV телеметрии продолжает работать отдельно.

## Источники и воспроизводимость

- [Исходный BQ40Z50 — SLUUA43A](https://www.ti.com/lit/ug/sluua43a/sluua43a.pdf)
- [R1 — SLUUBC1D](https://www.ti.com/lit/ug/sluubc1d/sluubc1d.pdf)
- [R2 — SLUUBK0B](https://www.ti.com/lit/ug/sluubk0b/sluubk0b.pdf)
- [R3 — SLUUBU5A](https://www.ti.com/lit/ug/sluubu5a/sluubu5a.pdf)
- [R4 — SLUUCH2](https://www.ti.com/lit/ug/sluuch2/sluuch2.pdf)
- [R5 — SLUUCN4B](https://www.ti.com/lit/ug/sluucn4b/sluucn4b.pdf)
- [Уточнение TI о формате RSOCWrite](https://e2e.ti.com/support/power-management-group/power-management/f/power-management-forum/845203/bq40z50-r3-device-fw-rsoc-write-command---0x0079)
- ABI CMAPI: источник и установка описаны в [EV2400_WINDOWS.md](EV2400_WINDOWS.md).

Для пересборки каталога преобразуйте эти PDF командой `pdftotext -layout` в `r0.txt` … `r5.txt`, затем из `electron_app` выполните `python scripts/build_catalog.py <папка_текстов>`. Проверьте изменения метаданных и запустите тесты: таблицы TI содержат пропуски и опечатки, поэтому в генераторе есть явно указанные исправления.

Проверки: `npm test`, `python -m unittest discover -s bridge -p "test_*.py" -v`, `npm run build`. Браузерный сценарий `test/browser/commands.playwright.js` запускается через Playwright CLI на Vite dev server; он использует настоящий каталог с подменённым IPC. Windows CI проверяет упакованный мост вместе с каталогом. Эти тесты не заменяют проверку новых команд на реальной батарее; EV2400 в этой среде отсутствует.
