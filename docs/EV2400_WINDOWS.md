# EV2400 / BQ40Z50 on Windows (Electron 2.1)

## Запуск

1. Установите bqStudio / bqTools SDK от TI. Нужны **CMAPI.dll**, **commmgr.exe** и зависимости из той же поставки TI. Не копируйте одну DLL отдельно. Сборка приложения не распространяет библиотеки TI.
2. Закройте bqStudio. Подключите EV2400 (VID `0451`, PID `0037`) и батарею к **Port 1 SMBus**: SMBC, SMBD, GND.
3. Запустите BQ_tester. `Find TI libraries` ищет компоненты в `C:\ti`, `C:\Texas Instruments`, а также `TI` и `Texas Instruments` внутри Program Files / Program Files (x86), включая вложенные папки.
4. Если установка не найдена, нажмите **TI libraries…** и выберите папку установки. Выбор сохраняется. Также поддерживается переменная окружения `BQ_TI_DIR` (если папка ещё не выбрана в интерфейсе).
5. Выберите установку и нажмите **Connect Device**. TI откроет первый свободный адаптер; при нескольких адаптерах оставьте подключённым нужный EV2400. Список показывает найденные установки TI, а не факт наличия USB-устройства.

В Windows-сборку включён x86 Python-мост: отдельно Python устанавливать не требуется. Electron остаётся x64. Нужна **32-битная CMAPI.dll**; несовпадение разрядности диагностируется до загрузки DLL. При ошибке загрузки зависимостей восстановите установку TI и требуемый ею Visual C++ Runtime, не смешивайте DLL разных выпусков.

Проверено автоматически: логика моста, формат данных, управление подключением, сборка интерфейса. Для подтверждения работы конкретной версии TI и адаптера обязательна аппаратная проверка ниже; успешная сборка её не заменяет.

## Что исправлено

- Удалены `node-hid`, перебор 48 размеров/типов отчётов и угадывание команд, адресов, смещений и порядка байтов. Никакие произвольные USB-пакеты конфигурации больше не отправляются.
- Используется документированный **CMAPI** (cdecl): `SetupAppwithFirstFreeAdapter`, `RegisterPIDwithCM`, `SDKReadSMBWord`, `SDKWriteSMBWordReadBlock`, `SDKCloseDevice`, `TerminateCM`. Названия `OpenEV2400` / `ReadSMBusWord` из первоначального отчёта не используются как предполагаемые экспорты.
- Чтения выполняются последовательно в отдельном процессе. Целевой период — 100 мс; фактическая частота зависит от времени ответов TI. Следующий цикл не пересекается с предыдущим. Зависший мост завершается по тайм-ауту, запоздалые ответы после отключения отбрасываются.
- Успех подключения требует успешного чтения напряжения батареи. Ошибки содержат исходный код и текст TI. При потере всех показаний соединение закрывается; частично недоступные поля имеют `null`, в интерфейсе — `N/A` / `UNKNOWN`.
- `0` и `0xFFFF` не считаются ошибками: например, ток `0xFFFF` означает −1 мА. SMBus-ошибки определяются по коду возврата API.
- SafetyStatus и OperationStatus читаются как 4-байтовые little-endian блоки. Документированные MAC-запросы `0x0051` и `0x0054` выбираются через ManufacturerAccess `0x00`, затем читаются из ManufacturerData `0x23`. Это позволяет читать их и в SEALED mode без unseal. Проверяется точная длина ответа. Прошивка, data flash, ключи и FET-команды не изменяются.
- Температура в IPC и CSV остаётся в исходных десятых кельвина (`Temp_0.1K`), отображение в °C: `raw / 10 - 273.15`.
- Исправлена карта флагов BQ40Z50, включая старшие биты защит, FUSE (5) и CB (28). Неопрошенные регистры показываются как `N/A`.

## Почему не достаточно заменить WriteFile на SetFeature

Ошибка Windows 87 сама по себе не доказывает отсутствие Interrupt OUT. Для прямого HID нужны дескриптор, правильный Report ID, длина **и протокол пакетов TI**. `node-hid` уже предоставляет `sendFeatureReport` / `getFeatureReport`; старый код их тоже перебирал. Успешная передача отчёта не подтверждает, что батарея выполнила нужное чтение. Выбран путь через документированный TI API, который берёт USB-протокол на себя.

Источники:

- [TI CMAPI 0.0.1.84, ABI и жизненный цикл Communication Manager](https://e2e.ti.com/cfs-file/__key/communityserver-discussions-components-files/196/CMAPI.dll_5F00_v0.0.1.84.pdf), §§4.1.2.1, 4.1.2.6, 4.1.2.24, 4.1.2.30–32. Используется константа `BACKGROUND = 1` из CMAPI.h; в описании аргумента §4.1.2.32 есть противоречащая ей опечатка.
- [TI BQ40Z50-R1 TRM, SLUUBC1D](https://www.ti.com/lit/ug/sluubc1d/sluubc1d.pdf), ManufacturerAccess, SafetyStatus, OperationStatus и SBS-команды. Дополнительные флаги более поздних ревизий могут требовать отдельного описания; полное исходное 32-битное значение сохраняется.
- [node-hid API](https://github.com/node-hid/node-hid#devicesendfeaturereportdata).

## Проверка на оборудовании

1. Запишите напряжение, ток, температуру, SoC и статусы в bqStudio, затем закройте его.
2. Подключитесь из BQ_tester. Сверьте значения с bqStudio, учитывая время между измерениями. Ожидается, например, `2982` → `25.1 °C`, а ток −1 мА не должен исчезать.
3. Проверьте нулевой ток / нулевые SafetyStatus и SoC, если такие состояния доступны. Нулевые значения должны сохраняться.
4. Отсоедините USB или SMBus. Приложение должно показать ошибку / отсутствие данных, не «нормальный» статус и не подставленную температуру. Затем повторите подключение.
5. Проверьте Disconnect → Connect и выход из приложения. После выхода bqStudio должен снова получать адаптер.
6. Если чтение не удалось, сохраните Debug Console, версию bqStudio, пути CMAPI.dll / commmgr.exe и версию firmware EV2400. Это позволит отличить ошибку установки/ABI от SMBus NACK и тайм-аута.

## Разработка и сборка

В `electron_app`:

```powershell
npm ci
npm test
python -m unittest discover -s bridge -p "test_*.py" -v
npm run build
```

Для запуска исходного моста на Windows нужен x86 Python 3.12 (`py -3-32`). Можно указать точный путь к интерпретатору через `BQ_PYTHON`. Мост не использует сторонние Python-пакеты.

Для Windows EXE (команда `python` должна запускать x86 Python):

```powershell
python -m pip install pyinstaller==6.11.1
python -m PyInstaller --noconfirm --clean --onedir --console --name ti-bridge --distpath bridge-dist --workpath bridge-build --specpath bridge-build --add-data "bridge/catalog.json;." bridge/ti_bridge.py
npm run electron:dist
```

GitHub Actions выполняет тесты, собирает x86-мост, проверяет его JSON-ответ без оборудования и наличие в упакованном приложении, затем загружает installer и portable EXE как artifact. Release создаётся только для тега `v*`.

Изменён только тракт `electron_app`. Старые `desktop_app`, прошивка MSP430 и WebSerial — отдельные реализации и этим исправлением не проверены.
